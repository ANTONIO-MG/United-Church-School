{% comment %} 500 — server error. DELIBERATELY SELF-CONTAINED. Django renders this one differently from the other error pages: `django.views.defaults.server_error` calls `template.render()` with **no request**, so NO context processors run — `dz_array`, `brand`, `strings`, `request` and `user` are all undefined here. Anything that depends on them fails *while handling a failure*, so the visitor gets a bare "A server error occurred" instead of this page, and the original traceback is masked. That is exactly what the previous version did: it inherited the theme's asset map and looped over `…|getdata:request.path`, which raised VariableDoesNotExist on every 500. So: no {% extends %}, no {% include %}, no {% static %} (a hashed-manifest miss would raise too), no external CSS or JS. Inline everything. If you edit this file, keep it standalone — and test it with `DEBUG = False` and a view that raises, not just by opening the file. 404 / 403 / 400 are NOT affected: their handlers do pass the request, so they can use the normal context. {% endcomment %} Server error · United Church School
